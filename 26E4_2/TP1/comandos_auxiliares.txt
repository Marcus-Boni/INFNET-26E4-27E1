1. INVESTIGAÇÃO DO COMANDO 'ls' COM: type, which E help
================================================================================
a) Comando 'type ls':
   Indica como o interpretador de comandos (shell) interpreta o nome 'ls' (se é
   um builtin do shell, palavra-chave, função, alias ou executável externo).
marcus@ubuntu-wsl:~$ type ls
ls is /usr/bin/ls

b) Comando 'which ls':
   Localiza o caminho absoluto do binário executável através da variável $PATH.
marcus@ubuntu-wsl:~$ which ls
/usr/bin/ls

c) Comando 'help' e 'ls --help':
   Nota técnica: O comando interno 'help' do Bash exibe documentação para comandos
   internos do shell (shell builtins, como 'cd', 'alias', 'type'). Como 'ls' é um
   binário externo (/usr/bin/ls), 'help ls' informa que não há builtin com esse nome,
   enquanto 'ls --help' exibe a ajuda embutida do próprio binário GNU coreutils:
marcus@ubuntu-wsl:~$ help ls 2>&1 || true
/workspace/run_exercises.sh: line 449: help: no help topics match `ls'.  Try `help help' or `man -k ls' or `info ls'.

2. INVESTIGAÇÃO DO COMANDO 'rm' COM: whatis, apropos, man E info
================================================================================
a) Comando 'whatis rm':
   Exibe uma descrição resumida de uma linha extraída do banco de dados de manpages.
marcus@ubuntu-wsl:~$ whatis rm
rm (1)               - remove files or directories

b) Comando 'apropos rm':
   Pesquisa nos nomes e descrições das páginas de manual por palavras-chave relacionadas.
marcus@ubuntu-wsl:~$ apropos -e rm
rm (1)               - remove files or directories

marcus@ubuntu-wsl:~$ apropos "remove files" | head -n 10
rm (1)               - remove files or directories

c) Comando 'man rm':
   Exibe a página completa do manual de referência tradicional do Unix/Linux (seção 1).
marcus@ubuntu-wsl:~$ man rm | head -n 35
RM(1)                            User Commands                           RM(1)

NAME
       rm - remove files or directories

SYNOPSIS
       rm [OPTION]... [FILE]...

DESCRIPTION
       This  manual  page  documents  the  GNU version of rm.  rm removes each
       specified file.  By default, it does not remove directories.

       If the -I or --interactive=once option is given,  and  there  are  more
       than  three  files  or  the  -r,  -R, or --recursive are given, then rm
       prompts the user for whether to proceed with the entire operation.   If
       the response is not affirmative, the entire command is aborted.

       Otherwise,  if  a file is unwritable, standard input is a terminal, and
       the -f or --force option is not given, or the -i  or  --interactive=al‐
       ways  option  is  given,  rm prompts the user for whether to remove the
       file.  If the response is not affirmative, the file is skipped.

OPTIONS
       Remove (unlink) the FILE(s).

       -f, --force
              ignore nonexistent files and arguments, never prompt

       -i     prompt before every removal

       -I     prompt once before removing more than three files, or  when  re‐
              moving  recursively;  less intrusive than -i, while still giving
              protection against most mistakes

       --interactive[=WHEN]

d) Comando 'info rm':
   Exibe a documentação hipertextual detalhada do projeto GNU (Texinfo / coreutils).

File: coreutils.info,  Node: rm invocation,  Next: shred invocation,  Prev: mv invocation,  Up: Basic operations

11.5 ‘rm’: Remove files or directories
======================================

‘rm’ removes each given FILE.  By default, it does not remove
directories.  Synopsis:

     rm [OPTION]... [FILE]...

   If the ‘-I’ or ‘--interactive=once’ option is given, and there are
more than three files or the ‘-r’, ‘-R’, or ‘--recursive’ are given,
then ‘rm’ prompts the user for whether to proceed with the entire
operation.  If the response is not affirmative, the entire command is
aborted.

   Otherwise, if a file is unwritable, standard input is a terminal, and
the ‘-f’ or ‘--force’ option is not given, or the ‘-i’ or
‘--interactive=always’ option _is_ given, ‘rm’ prompts the user for
whether to remove the file.  If the response is not affirmative, the
file is skipped.

   Any attempt to remove a file whose last file name component is ‘.’ or
‘..’ is rejected without any prompting, as mandated by POSIX.

   _Warning_: If you use ‘rm’ to remove a file, it is usually possible
to recover the contents of that file.  If you want more assurance that
the contents are unrecoverable, consider using ‘shred’.
